## 3. Security requirements

1. QR tokens must be generated by the backend.
2. Never generate QR security tokens in React.
3. Never put vehicle or personal information directly into QR content.
4. Public navigation must validate the token before showing protected ticket details.
5. Public navigation must not consume a reusable navigation token.
6. Staff ticket validation must retain its separate single-use behavior.
7. Invalid, expired, revoked and completed tickets must not expose protected information.
8. The frontend must not mark a parking bay vacant before the backend confirms exit.

## 5. Acceptance test checklist

### Vehicle entry
- [ ] Valid Indian registration is accepted.
- [ ] Invalid registration is rejected.
- [ ] Vehicle type is saved correctly.
- [ ] Duplicate active vehicle entry is prevented.
- [ ] API failure is displayed clearly.
- [ ] Successful creation returns the expected session/ticket data.

### Smart allocation
- [ ] Available spaces are displayed.
- [ ] Preferences affect recommendations when supported.
- [ ] Allocation confirmation reaches the backend.
- [ ] A slot conflict is handled without creating a false success state.
- [ ] No-space state is displayed correctly.

### Active parking
- [ ] Active sessions load from the backend.
- [ ] Vehicle and slot details match backend records.
- [ ] Search and filters work.
- [ ] Refresh updates the displayed sessions.
- [ ] API errors are distinguishable from an empty session list.

### Exit
- [ ] Correct session is selected.
- [ ] Cancellation does not call the exit operation.
- [ ] Confirmation calls the backend once.
- [ ] Failed exit does not mark the session completed.
- [ ] Slot becomes available only after backend confirmation.

### Reservations
- [ ] Reservation list loads.
- [ ] Valid reservation can be created.
- [ ] Invalid reservation is rejected.
- [ ] Cancellation updates the reservation state.
- [ ] API failures are displayed.

### Tickets and QR
- [ ] Ticket details match backend data.
- [ ] QR token comes from the backend.
- [ ] QR opens the public navigation route.
- [ ] Invalid token is rejected.
- [ ] Expired/revoked/completed token is rejected.
- [ ] Active navigation does not consume the reusable token.
- [ ] Staff single-use validation remains separate.

### Driver navigation
- [ ] Navigation works without staff login.
- [ ] Ticket details appear only after token validation.
- [ ] Destination and route instructions are displayed when available.
- [ ] Missing route data has a clear fallback.
- [ ] Invalid token and backend-unavailable states are distinguishable.

### History
- [ ] Completed sessions load.
- [ ] Search and filters work.
- [ ] Sorting and pagination work.
- [ ] CSV export contains the displayed records.
